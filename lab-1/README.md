# Лабораторная работа № 1: распознавание персональных данных

Этот файл объясняет работу проекта с самого начала. Для понимания не требуется
предварительное знание машинного обучения, нейронных сетей или обработки текста.

Основная программа находится в [`main.ipynb`](./main.ipynb). Это Jupyter
Notebook: документ, в котором обычный текст с объяснениями чередуется с
исполняемыми блоками Python-кода.

## 1. Что требуется сделать

Программа получает произвольный текст и должна найти в нём персональные данные.
В работе распознаются восемь классов:

| Метка | Что означает | Пример |
|---|---|---|
| `NAME` | имя человека | `Борис` |
| `SURNAME` | фамилия | `Громов` |
| `EMAIL` | электронная почта | `ivanov@example.ru` |
| `INN` | ИНН физического или юридического лица | `7707083893` |
| `PHONE` | российский телефон | `+7 (999) 123-45-67` |
| `BANK_CARD` | номер банковской карты | `4111 1111 1111 1111` |
| `SNILS` | СНИЛС | `112-233-445 95` |
| `PASSPORT` | серия и номер российского паспорта | `45 08 123456` |

Результат должен иметь вид:

```python
[название_класса, начальный_индекс, конечный_индекс]
```

Например:

```python
text = "Борис получил письмо"
["NAME", 0, 5]
```

Числа `0` и `5` — символьные координаты слова `Борис`. Правая граница не
включается, как в обычном срезе Python:

```python
text[0:5] == "Борис"
```

Координаты нужны, чтобы в следующей работе можно было обезличить текст, например
заменить найденное имя на `[NAME]`.

## 2. Что такое NER и token classification

**NER (Named Entity Recognition)** — поиск именованных сущностей в тексте.
Сущностью может быть человек, организация, адрес, телефон, документ и так далее.

В этой работе NER рассматривается как задача **token classification**. Текст
сначала делится на токены, после чего каждому токену назначается ровно одна
метка.

Токен — это небольшая часть текста: слово, число, знак пунктуации или часть
слова. Например:

```text
Борис | Громов | , | телефон | + | 7 | ...
```

Каждый токен относится либо к одному классу ПДн, либо к классу `O`, означающему
«не персональные данные».

## 3. Что такое BIO-разметка

Если сущность состоит из нескольких токенов, необходимо понимать, где она
начинается и где продолжается. Для этого используется схема BIO:

- `B` — beginning, первый токен сущности;
- `I` — inside, продолжение той же сущности;
- `O` — outside, токен не относится к сущности.

Пример:

| Токен | BIO-метка |
|---|---|
| `Борис` | `B-NAME` |
| `Громов` | `B-SURNAME` |
| `телефон` | `O` |
| `+` | `B-PHONE` |
| `7` | `I-PHONE` |
| `999` | `I-PHONE` |

В обучаемой части программы используются пять меток:

```text
O, B-NAME, I-NAME, B-SURNAME, I-SURNAME
```

Остальные шесть классов определяются строгими правилами, но итоговый результат
для них тоже преобразуется в BIO.

## 4. Почему решение гибридное

В программе соединены два подхода.

### 4.1. Нейронная модель для имён и фамилий

У имени и фамилии нет уникального строгого формата. Слово `Роман`, например,
может быть именем человека, а может обозначать литературное произведение.
Простой поиск по списку слов не понимает контекст и не распознаёт новые фамилии.

Поэтому `NAME` и `SURNAME` определяет обученная модель RuBERT.

### 4.2. Правила для структурированных данных

Телефон, ИНН, банковская карта и другие номера имеют устойчивую структуру.
Для них регулярное выражение проще, быстрее и предсказуемее нейросети.

Например, телефон может иметь вид:

```text
+7 (999) 123-45-67
```

Регулярное выражение описывает допустимые цифры, скобки, пробелы и дефисы.

Таким образом:

```text
текст
 ├─ RuBERT → NAME, SURNAME
 └─ регулярные выражения и проверки → остальные 6 классов
                      ↓
            объединённый список сущностей
```

## 5. Что такое factRuEval-2016

[`factRuEval-2016`](https://github.com/dialogue-evaluation/factRuEval-2016) —
русскоязычный размеченный набор текстов для оценки систем извлечения фактов и
именованных сущностей.

Он содержит:

- исходные русские тексты;
- разбиение текста на токены;
- символьные границы сущностей;
- тип каждой сущности;
- связи между упоминаниями объектов.

В работе используются типы `name` и `surname`. После загрузки набора программа
нашла:

- 254 документа;
- 1343 размеченных имени;
- 1966 размеченных фамилий.

Набор скачивается из официального репозитория автоматически. Хранить его в Git
не нужно: это производный файл, который всегда можно скачать повторно.

Для чтения формата используется функция `load_factru` из библиотеки `corus`.

## 6. Что такое RuBERT

В работе используется модель
[`DeepPavlov/rubert-base-cased`](https://huggingface.co/DeepPavlov/rubert-base-cased).

RuBERT — русскоязычная версия архитектуры BERT. До начала нашей работы модель уже
была предварительно обучена на большом количестве русских текстов. Поэтому она
знает закономерности русского языка и контекст слов, но изначально не умеет
решать именно нашу задачу с метками `NAME` и `SURNAME`.

Мы выполняем **fine-tuning** — дополнительное обучение готовой модели на
factRuEval. Вместо обучения языковой модели с нуля мы добавляем классификатор на
пять BIO-меток и немного изменяем все веса модели под конкретную задачу.

`cased` в названии означает, что модель различает регистр букв. Для NER это
полезно: слова с заглавной буквы чаще оказываются именами собственными.

### Упрощённый принцип работы BERT

BERT рассматривает слово с учётом слов слева и справа. Механизм attention
определяет, какие части предложения важны друг для друга. Поэтому одинаковое
слово в разных предложениях может получить разные внутренние представления.

После BERT для каждого токена получается набор чисел — вектор признаков.
Классификационный слой преобразует его в вероятности BIO-меток. Метка с самой
большой вероятностью становится предсказанием.

## 7. Токенизация WordPiece

RuBERT не работает напрямую с обычными словами. `AutoTokenizer` делит текст на
WordPiece-субтокены. Редкое слово может быть разбито на несколько частей.

У исходного слова одна правильная BIO-метка, а субтокенов может быть несколько.
В этой работе метка назначается только первому субтокену. Для остальных ставится
значение `-100`.

В PyTorch `-100` означает: не учитывать эту позицию при вычислении функции
потерь. То же значение получают служебные токены модели.

Это предотвращает многократный учёт одного слова и соответствует руководству
Hugging Face по token classification.

## 8. Символьные координаты и перенос разметки

factRuEval хранит начало и конец каждой сущности в исходном тексте. Токенизатор
RuBERT также возвращает `offsets` — символьные границы каждого токена.

Функция `find_person_span` проверяет пересечение границ токена с границами
размеченной сущности:

```python
token_start < span.stop and span.start < token_end
```

Если пересечение найдено, токен получает `NAME` или `SURNAME`. Первый токен
спана получает `B-`, следующие — `I-`. Если пересечения нет, назначается `O`.

## 9. Почему документы делятся на блоки

RuBERT может обработать не более 512 субтокенов за один проход. Некоторые
документы factRuEval длиннее.

Если использовать только `truncation=True`, конец документа будет потерян.
Поэтому `return_overflowing_tokens=True` разбивает весь документ на несколько
последовательных блоков длиной до 512 токенов.

Сначала разделяются целые документы, и только потом создаются блоки. Это важно:
части одного документа не должны одновременно попасть в обучение и тест, иначе
оценка будет завышенной из-за утечки данных.

## 10. Разделение данных

Документы случайно перемешиваются с фиксированным `seed=42` и делятся так:

- 80% — `train`, обучение модели;
- 10% — `valid`, выбор лучшей эпохи;
- 10% — `test`, окончательная независимая проверка.

Фиксированный seed обеспечивает воспроизводимость: при повторном запуске
получается то же самое разделение.

После нарезки документов получилось:

- 265 обучающих блоков;
- 32 проверочных блока;
- 33 тестовых блока.

Тестовая часть не используется ни для изменения весов, ни для выбора лучшей
эпохи.

## 11. Как проходит обучение

Основные параметры:

| Параметр | Значение | Смысл |
|---|---:|---|
| `learning_rate` | `2e-5` | размер шага изменения весов |
| `num_train_epochs` | `7` | семь проходов по обучающим данным |
| train batch | `8` | число примеров в одном мини-батче |
| eval batch | `16` | размер батча при оценке |
| `gradient_accumulation_steps` | `2` | накопление градиентов двух батчей |
| `weight_decay` | `0.01` | регуляризация весов |
| `fp16` | при наличии GPU | ускоренное обучение на CUDA |

После каждой эпохи модель проверяется на `valid`. `Trainer` сохраняет checkpoint
и в конце возвращает вариант с лучшей F1.

Обученная модель сохраняется в `res_model_base`. При следующем запуске ноутбук
видит `res_model_base/config.json`, загружает готовую модель и не обучает её
повторно.

Модель занимает около 680 МБ, поэтому она не добавляется в Git. GitHub не
принимает обычные файлы больше 100 МБ. Если папки модели нет, ноутбук обучит и
сохранит её заново.

## 13. Исправление кодировки Windows

Файлы factRuEval сохранены в UTF-8. Старая версия `corus` открывает основной
текст без явного указания кодировки. На Linux кодировкой по умолчанию обычно
является UTF-8, а в Windows Python может выбрать CP1251.

Поэтому в ноутбуке выполняется небольшая совместимая настройка:

```python
factru_source.load_text = lambda path: Path(path).read_text(encoding="utf-8")
```

Она не изменяет данные, а только явно сообщает способ их чтения.

## 14. Регулярные выражения

Регулярное выражение — шаблон, описывающий допустимую последовательность
символов. Например, шаблон e-mail ищет локальную часть, символ `@`, домен и
доменную зону.

Программа использует отдельные шаблоны для:

- e-mail;
- телефона;
- банковской карты;
- ИНН из 10 или 12 цифр;
- СНИЛС;
- паспорта.

Одного совпадения с форматом недостаточно. Случайный набор цифр может выглядеть
как ИНН или карта. Поэтому применяются контрольные алгоритмы.

## 15. Проверка контрольных разрядов

### ИНН

Для 10- и 12-значного ИНН используются разные последовательности весовых
коэффициентов. Каждая цифра умножается на свой вес, результаты складываются,
после чего применяются остатки от деления на 11 и 10. Полученное значение должно
совпасть с контрольной цифрой ИНН.

Для 12-значного ИНН проверяются две последние цифры.

### Банковская карта

Используется алгоритм Луна:

1. цифры через одну удваиваются;
2. если результат больше 9, из него вычитается 9;
3. все значения складываются;
4. итоговая сумма должна делиться на 10 без остатка.

Это проверяет структуру номера, но не существование карты и не наличие денег.

### СНИЛС

Первые девять цифр умножаются на веса от 9 до 1. По сумме вычисляется двузначное
контрольное число, которое сравнивается с последними двумя цифрами.

Паспорт и телефон не имеют контрольного разряда, поэтому для них проверяются
формат и контекст.

## 16. Как объединяются результаты

Функция `find_structured` находит структурированные атрибуты. `person_ner`
возвращает имена и фамилии. Функция `recognize` объединяет оба результата.

Если два кандидата пересекаются, применяется только один. Это выполняет условие

Результат сортируется по начальному индексу и преобразуется в списки:


## 17. Метрики качества

Для понимания метрик используются три числа:

- **TP (true positive)** — сущность существует и найдена правильно;
- **FP (false positive)** — программа нашла сущность там, где её нет;
- **FN (false negative)** — сущность существует, но программа её пропустила.

### Precision

```text
precision = TP / (TP + FP)
```

Показывает, какая доля найденных сущностей действительно правильная. Высокая
precision означает мало ложных срабатываний.

### Recall

```text
recall = TP / (TP + FN)
```

Показывает, какую долю существующих сущностей программа нашла. Высокий recall
означает мало пропусков.

### F1

```text
F1 = 2 × precision × recall / (precision + recall)
```

F1 — гармоническое среднее precision и recall. Оно становится высоким, только
если обе метрики высокие.

### Средневзвешенная F1

F1 вычисляется отдельно для каждого класса. Затем значения умножаются на число
истинных примеров соответствующего класса, складываются и делятся на общее число
примеров:

```text
weighted F1 = Σ(F1 класса × support класса) / Σ support
```

`support` — количество истинных сущностей класса в тесте.

## 23. Короткие ответы на возможные вопросы

**Почему нельзя использовать только регулярные выражения?**

У имени и фамилии нет уникального формата. Нужен контекст предложения.

**Почему нельзя использовать только RuBERT?**

Строгие номера эффективнее распознавать правилами. Кроме того, контрольное число
является точным математическим условием, которое нейросеть не гарантирует.

**Зачем нужен valid, если есть test?**

Valid используется для выбора лучшей эпохи. Test используется один раз для
независимой итоговой оценки.

**Что такое эпоха?**

Один полный проход модели по всей обучающей выборке.

**Что такое batch?**

Небольшая группа примеров, обрабатываемых одновременно перед одним обновлением
весов.

**Что такое функция потерь?**

Число, показывающее степень расхождения предсказаний модели с правильными
метками. При обучении модель старается уменьшить это число.

**Почему F1 не равна accuracy?**

Большинство токенов имеет класс `O`. Модель могла бы получить высокую accuracy,
предсказывая `O` почти везде, но не находить сущности. F1 по сущностям лучше
отражает качество NER.

**Проверка Луна подтверждает настоящую банковскую карту?**

Нет. Она подтверждает только математическую корректность номера.

**Почему модель может иногда ошибаться на имени?**

NER — вероятностная задача. Результат зависит от контекста, состава обучающих
данных и количества обучения. Именно поэтому качество оценивается метриками на
отдельной тестовой выборке.

## 24. Ограничения решения

- Телефонные регулярные выражения ориентированы на российские номера.
- Паспорт определяется по российскому формату и слову-контексту `паспорт`.
- Правильное контрольное число не доказывает существование документа.
- RuBERT может ошибаться на редких именах, иностранных написаниях и текстах без
  контекста.
- Синтетические структурированные тесты проверяют поддерживаемые форматы, но не
  заменяют полностью вручную размеченный реальный корпус.

Эти ограничения нормальны для учебной работы. Они показывают, где систему можно
развивать дальше: расширять форматы, добавлять реальные размеченные данные и
дообучать модель на большем корпусе.
